# hub shell completion

`hub-completion.sh` wires tab-completion for the `hub` CLI into bash and zsh
(one file; it detects the running shell and uses the right completion
machinery). It calls the hidden zero-dependency verb `hub __complete`, which
emits candidates one per line — so the runtime CLI needs no completion library.

Flags the verb requires carry a trailing `*` in the menu (`--title*` for
`hub add-task`) and are listed FIRST. The marker is display-only — inserted
text is always the clean flag name, so the CLI never sees it. zsh pairs the
marked menu entry with clean insertion (`compadd -d`). bash's readline prints
its ambiguous-completion list verbatim, so the marker stays visible in the
bash menu too: the wiring captures the marked candidates with `mapfile` (an
unquoted `$(...)` capture would pathname-expand the `*` against files in the
current directory), preserves required-first order by turning off readline's
alphabetical re-sort (`compopt -o nosort`), and strips the marker exactly
when a single candidate would be inserted whole — the common-prefix insertion
bash performs for multiple candidates can never include a trailing marker.
The legacy compctl branch (old zsh) inserts what it displays, so it strips
the marker outright.

The script is generated by `scripts/generate-completion.mjs`, which uses
omelette (a devDependency) for the shell boilerplate and swaps omelette's
internal invocation for the public `__complete` verb. Regenerate after
cloning or after an omelette upgrade with:

```sh
npm install        # brings in devDependencies, incl. omelette
node scripts/generate-completion.mjs
```

## Installing (bash-completion is a runtime requirement for bash)

**bash**: the wiring calls `_get_comp_words_by_ref` and
`__ltrim_colon_completions`, which ship with the **`bash-completion` package,
not with bash itself**. Without it, `source`ing succeeds silently but the
first `hub <TAB>` fails ("command not found" or nothing). Install it first
(e.g. `pacman -S bash-completion`, `apt install bash-completion`,
`brew install bash-completion`).

The easiest install — and the standard bash-completion mechanism — is the
`hub install-completion` verb: it copies the script to
`~/.local/share/bash-completion/completions/hub`, where bash-completion's
lazy loader sources it automatically on the first `hub <TAB>` (no rc edit):

```sh
hub install-completion              # bash (default)
hub install-completion --shell zsh  # zsh — copies to ~/.hub/completion and
                                    # prints the source line to add
```

Or wire it by hand (older bash-completion versions, or if you prefer an
explicit rc line). In every case the script needs a `hub` command on your
`PATH` (e.g. the `bin` entry from a global npm install, or an alias/symlink
to `node /path/to/personal-hub/src/hub.ts`):

**bash** — add to `~/.bashrc` (after bash-completion has been sourced):

```bash
source /path/to/personal-hub/completion/hub-completion.sh
```

**zsh** — add to `~/.zshrc` (after `compinit` has run, as in default setups):

```zsh
source /path/to/personal-hub/completion/hub-completion.sh
```

Then `exec` a new shell (or re-source) and try:

```sh
hub <TAB>                        # all verbs
hub add-<TAB>                    # add-* verbs
hub add-interaction --<TAB>      # that verb's flags
hub add-task --person <TAB>      # live person slugs from the DB
hub add-task --status <TAB>      # ready / in-progress / completed
```

`--db <path>` typed before the verb is honored — live candidates (slugs,
interaction kinds) come from that database, not the default one.
