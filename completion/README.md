# hub shell completion

`hub-completion.sh` wires tab-completion for the `hub` CLI into bash and zsh
(one file; it detects the running shell and uses the right completion
machinery). It calls the hidden zero-dependency verb `hub __complete`, which
emits candidates one per line — so the runtime CLI needs no completion library.

The script is generated by `scripts/generate-completion.mjs`, which uses
omelette (a devDependency) for the shell boilerplate and swaps omelette's
internal invocation for the public `__complete` verb. Regenerate after
cloning or after an omelette upgrade with:

```sh
npm install        # brings in devDependencies, incl. omelette
node scripts/generate-completion.mjs
```

## Wiring

The script expects a `hub` command on your `PATH` (an alias or symlink to
`node /path/to/personal-hub/src/hub.ts` — the repo has no install step).

**bash** — add to `~/.bashrc`:

```bash
source /path/to/personal-hub/completion/hub-completion.sh
```

**zsh** — add to `~/.zshrc` (after `compinit` has run, as in default setups):

```zsh
source /path/to/personal-hub/completion/hub-completion.sh
```

Then `exec` a new shell (or re-source) and try:

```sh
hub <TAB>                        # all verbs
hub add-<TAB>                    # add-* verbs
hub add-interaction --<TAB>      # that verb's flags
hub add-task --person <TAB>      # live person slugs from the DB
hub add-task --status <TAB>      # ready / in-progress / completed
```

`--db <path>` typed before the verb is honored — live candidates (slugs,
interaction kinds) come from that database, not the default one.
